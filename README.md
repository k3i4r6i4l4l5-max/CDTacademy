# Практика

Учебная платформа: конспекты, тесты с автоматической и ручной проверкой, группы студентов и панель преподавателя/администратора. Также есть самостоятельная программа JavaScript из 9 уроков и 27 заданий.

## Стек

| Часть | Технологии |
|---|---|
| Приложение и маршруты | Nuxt 4, Vue 3 |
| Язык | TypeScript, Vue SFC с `<script setup lang="ts">` |
| Стили | Tailwind CSS 4 через Vite, CSS для авторизации и панели |
| Редактор кода | CodeMirror 6, поддержка JavaScript |
| Сервер | Nitro/H3 внутри Nuxt, Node.js |
| Хранение | JSON-файл на сервере, localStorage для черновиков и самостоятельной практики |
| Пароли и сессии | Node.js crypto: scrypt, соль, HttpOnly cookie |
| Проверки | vue-tsc / Nuxt typecheck, Playwright, Node.js assert |

Vue, Vite, Nitro и H3 подключаются через Nuxt. Точные версии установленных зависимостей фиксируются в `package-lock.json`. Внешняя база данных для локального запуска не нужна.

## Требования

- Node.js **24.15.0 или новее в ветке 24** — проверенный вариант для проекта.
- Установленная версия Nuxt также допускает Node.js `^22.22.3` или `>=26.0.0`.
- npm, поставляемый вместе с Node.js.
- Для браузерных тестов — Chromium из Playwright или установленный Google Chrome.

## Локальный запуск

В PowerShell:

```powershell
cd "C:\Users\cyber\Desktop\CDTacademy"
npm ci
npm run dev
```

`npm ci` устанавливает зависимости по lock-файлу и автоматически запускает `nuxt prepare`. При первом запуске нужен доступ к npm registry. После изменения зависимостей используйте `npm install`, чтобы обновить lock-файл.

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Оставляйте терминал с сервером открытым; `Ctrl+C` останавливает приложение. Если порт занят, используйте адрес, напечатанный Nuxt в терминале.

`.env` для стандартного запуска не требуется. Дополнительные настройки перечислены в `.env.example`.

## Базовые аккаунты

| Роль в форме входа | Логин | Пароль |
|---|---|---|
| Студент | `Студент 1` | `123` |
| Преподаватель | `Препод 1` | `Препод 1` |
| Администратор | `Админ` | `Админ123` |

Логины и буквенная часть паролей в таблице написаны **кириллицей**. Пароли чувствительны к регистру. При входе нужно выбрать соответствующую роль: верный пароль студента не позволит войти как преподаватель.

Эти аккаунты создаются автоматически при первом обращении к серверному хранилищу, если файл данных ещё отсутствует. Существующие аккаунты и пароли при перезапуске не перезаписываются. Это демонстрационные данные для локальной разработки.

Самостоятельная регистрация открыта **только студентам**. На форме регистрации нет селектора роли: сервер проверяет роль `student`. Преподавателей и администраторов создаёт администратор в разделе **«Студенты и группы → Добавить пользователя»**. Там он назначает логин, пароль, роль и, при необходимости, группу студента.

## Роли и страницы

| Роль | Возможности |
|---|---|
| Студент | Регистрация, выбор группы, чтение опубликованных конспектов, прохождение тестов, просмотр своих оценок и комментариев |
| Преподаватель | Тесты и конспекты, публикация, проверка ответов, фильтры результатов, подсчёт прошедших, смена группы студента |
| Администратор | Всё перечисленное для преподавателя, создание аккаунтов, назначение/снятие роли преподавателя, общая аналитика |

Роли проверяются на сервере. Изменение группы доступно преподавателю и администратору; назначение ролей — только администратору. Существующий аккаунт администратора нельзя понизить через форму изменения роли.

| Адрес | Назначение |
|---|---|
| `/` | Главная; у студента — опубликованные материалы преподавателей |
| `/login` | Вход; `/login?register=1` открывает регистрацию студента |
| `/learn` | Самостоятельная программа JavaScript с локальным прогрессом |
| `/tests` | Опубликованные тесты и отправленные попытки |
| `/notes` | Библиотека опубликованных конспектов |
| `/profile` | Профиль и выбор учебной группы |
| `/admin` | Управление обучением для преподавателя и администратора |

Начальные группы: **ИС-11, ИС-12, ПИ-11**.

## Тесты, конспекты и проверка ответов

У теста есть конспект, статус публикации, вопросы с баллами и проходной порог от 0 до 100% включительно. Например, **60% при пороге 60% считается прохождением**, когда оценены все ответы.

| Тип ответа | Проверка |
|---|---|
| Короткий ответ по эталону | Точное сравнение текста с учётом регистра; внешние пробелы удаляются |
| Один вариант | Совпадение с выбранным эталонным вариантом |
| Произвольный текст | Преподаватель выставляет баллы и комментарий |
| Код JavaScript | Преподаватель оценивает код вручную |
| Код по эталону | Автоматическое сравнение текста кода; игнорируются внешние пробелы и различия CRLF/LF |

До завершения ручной проверки процент предварительный. В результатах доступны фильтры по тесту, студенту, статусу и проценту **меньше или равно X**. Успешные попытки и уникальные прошедшие студенты считаются отдельно.

Конспекты создаются в отдельном разделе панели. Можно ввести текст, импортировать `.md`/`.txt`, посмотреть предпросмотр и опубликовать материал. Блок кода обозначается тройными обратными кавычками. HTML не исполняется. Если выбрать в тесте **«Связанный конспект»**, студенты будут получать его актуальный опубликованный текст.

Страницы автоматически обновляют материалы, оценки и группы каждые 5 секунд в видимой вкладке и при возвращении к ней. Черновики не показываются студентам. Изменённый открытый тест нужно обновить перед отправкой; ответы на неизменённые вопросы сохраняются. У уже отправленных попыток остаётся снимок прежних условий и порога.

## Хранение данных

- **Сервер:** `.data/platform.json` — пользователи, хеши паролей, сессии, группы, тесты, конспекты и попытки. Содержимое сохраняется после перезапуска.
- **Черновики тестов:** localStorage, ключи вида `practice:test:<userId>:<testId>`.
- **Самостоятельная программа `/learn`:** localStorage, ключ `practice:javascript:v2`. Это прогресс текущего браузера, отдельный от серверных результатов тестов.

Не удаляйте `.data/platform.json`, чтобы не потерять пользователей и результаты. Для резервной копии сохраняйте этот файл при остановленном сервере. Переменная `PLATFORM_DATA_FILE` позволяет задать другой путь к нему.

Хранилище рассчитано на **один серверный процесс** с постоянным диском. Подробнее: [архитектура](docs/architecture.md).

## Команды и проверки

| Команда | Назначение |
|---|---|
| `npm run dev` | Локальная разработка на `127.0.0.1` |
| `npm run typecheck` | Проверка типов |
| `npm run build` | Production-сборка с Node-сервером |
| `npm run preview` | Локальный просмотр готовой production-сборки |
| `npm run generate` | Статическая сборка публичной учебной части |
| `npm test` | Статическая сборка и браузерная проверка `/learn` |
| `npm run test:admin` | Серверная сборка и интеграционные/браузерные проверки платформы |

Подготовка браузера и запуск проверок:

```powershell
npx playwright install chromium
npm run typecheck
npm test
npm run test:admin
```

Вместо загрузки Chromium можно использовать установленный Chrome:

```powershell
$env:PLAYWRIGHT_CHANNEL = "chrome"
npm run test:admin
```

Тесты проверяют роли, регистрацию, оценки, публикацию, синхронизацию, редактор кода и мобильную компоновку. Административный сценарий запускает отдельный сервер на порту `3107`, использует временный файл данных и не меняет рабочую базу. Скриншоты проверок создаются в `test/*.png` и исключены из Git.

## Production-запуск

```powershell
npm ci
npm run build
node .output/server/index.mjs
```

Используйте адрес из вывода сервера. Для другого порта в PowerShell перед запуском можно задать `$env:NITRO_PORT = "3001"`. Переменные окружения для production передавайте процессу Node; сервер готовой сборки не загружает `.env` автоматически.

Полная платформа с регистрацией и API требует Node-сервера. `npm run generate` не заменяет её развёртывание. Для обновления приложения сохраняйте рабочий файл `.data/platform.json` и постоянный путь к нему.
