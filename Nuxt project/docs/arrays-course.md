# Массивы JavaScript: от первого элемента до обработки данных интерфейса

Учебный конспект на основе `js_arrays_handbook.md`. Это последовательный модуль после основ JavaScript: переменных, типов, условий и функций. Основная часть не требует знания React или Vue. Код примеров — JavaScript; реализация платформы остаётся на TypeScript.

## Как проходить

В каждом уроке: объяснение → разобранный пример → короткая практика → самостоятельная задача → проверка границ. На один урок отводится примерно 25–40 минут. Не нужно изучать все методы за один день. После каждого раздела предусмотрена контрольная работа.

Все ответы — исполняемый код. В короткой практике реализуйте `solution()`, в задачах — функцию с указанным именем. Результат возвращайте через `return`. Вывод в консоль не заменяет возвращаемое значение. Похожие реализации приведены перед заданиями; они показывают подход, но решают другую задачу.

Если не указано иное, массивы плотные, числа конечные, объекты имеют описанные поля. Неверные типы входа обрабатываются только там, где это явно требуется. Неизменность исходного массива является отдельным требованием: одного правильного результата недостаточно.

## 1. Создание массива, индексы и длина

Массив — упорядоченная коллекция. Первый элемент имеет индекс `0`, последний — `length - 1`. Чтение не изменяет массив. `at(-1)` читает последний элемент, а запись `array[-1]` обращается к свойству с ключом `"-1"`, а не к последнему элементу.

```js
const cities = ["Пермь", "Омск", "Тула"];
const first = cities[0];       // "Пермь"
const last = cities.at(-1);    // "Тула"
const size = cities.length;    // 3
const missing = cities[3];     // undefined
```

Разбор: сначала создаётся массив из трёх строк. Индекс `0` возвращает строку, `length` — число. Выход за пределы при чтении возвращает `undefined`. В пустом массиве и `[0]`, и `.at(-1)` дают `undefined`.

**Короткая практика.** В `solution()` создайте `fruits` из строк `"яблоко"`, `"груша"`, `"слива"`, `"лимон"`. Верните объект `{ first, last, length }`, где последнее значение получено через `at(-1)`. Ожидается `{ first: "яблоко", last: "лимон", length: 4 }`.

**Задача `edges(items)`.** Верните `[первый элемент, последний элемент]`. Для пустого входа верните `[]`. Массив не меняйте.

Проверки: `[10, 20, 30] → [10, 30]`; `[7] → [7, 7]`; `[] → []`.

Типичная ошибка: использовать `items.length` как индекс последнего элемента.

## 2. Изменение элемента и возвращаемое значение

`items[index] = value` изменяет массив. Само выражение присваивания возвращает присвоенное значение. `const` запрещает присвоить переменной другой массив, но позволяет менять элементы существующего.

```js
const scores = [3, 4, 5];
const assigned = (scores[1] = 9);
// scores: [3, 9, 5]
// assigned: 9
```

Разбор: индекс `1` обозначает второй элемент. Переменная `assigned` содержит число, а не изменённый массив. Запись далеко за пределами массива создаёт пропуски; `delete items[i]` также оставляет пропуск. Для удаления со сдвигом позже изучим `splice`.

**Короткая практика.** В `solution()` измените второй элемент `[10, 20, 30]` на `99`, верните массив. Ожидается `[10, 99, 30]`.

**Задача `replaceAt(items, index, value)`.** Измените элемент исходного массива и верните тот же массив. Если целочисленный индекс меньше `0` или не меньше длины, ничего не меняйте.

Проверки: `([1, 2], 0, 8) → [8, 2]`; `([1], 1, 8) → [1]`; `([], 0, 8) → []`. Дополнительно проверяется совпадение ссылки результата с входом.

## 3. Ссылки и поверхностная копия

Присваивание массива другой переменной не создаёт копию. Обе переменные указывают на одну коллекцию. Spread `[...items]` создаёт новый внешний массив; вложенные объекты при этом остаются общими.

```js
const original = [10, 20];
const alias = original;
alias[0] = 99;
// original тоже стал [99, 20]

const copy = [...original];
copy[0] = 5;
// copy: [5, 20], original: [99, 20]
```

Разбор: `alias === original` — `true`, `copy === original` — `false`. Изменение числа внутри новой копии не затрагивает исходный массив. Но для `[{ value: 1 }]` операция `copy[0].value = 2` изменит общий объект.

**Короткая практика.** Создайте копию `[1, 2]`, добавьте в копию число `3`. Верните `{ original, copy }`. Ожидается `{ original: [1, 2], copy: [1, 2, 3] }`.

**Задача `withFirst(items, value)`.** Верните новый массив с заменённым первым элементом. Пустой вход превращается в `[value]`. Исходный массив не менять.

Проверки: `([1, 2], 9) → [9, 2]`; `([], 9) → [9]`. Проверяются исходное содержимое и новая ссылка.

## 4. Конец массива: push и pop

`push(...values)` добавляет элементы в конец, меняет массив и возвращает новую длину. `pop()` удаляет последний элемент, меняет массив и возвращает удалённое значение. Для пустого массива `pop()` возвращает `undefined`.

```js
const history = ["Главная"];
const size = history.push("Поиск", "Профиль"); // 3
const closed = history.pop();                  // "Профиль"
// history: ["Главная", "Поиск"]
```

Разбор: после добавления длина равна трём. После удаления в `closed` находится строка, в `history` — оставшиеся две строки. Такая работа с концом массива лежит в основе стека: последним добавили — первым забрали.

**Короткая практика.** Создайте пустой `cart`, добавьте `"milk"`, затем одним вызовом `"bread"` и `"eggs"`. Верните результат последнего `push`. Ожидается `3`.

**Задача `takeLast(items)`.** Удалите последний элемент исходного массива. Верните `{ removed, remaining }`, где `remaining` — тот же входной массив.

Проверки: `[1, 2, 3] → { removed: 3, remaining: [1, 2] }`; `[] → { removed: undefined, remaining: [] }`.

## 5. Начало массива: unshift и shift

`unshift(...values)` добавляет в начало и возвращает новую длину. `shift()` удаляет первый элемент и возвращает его, либо `undefined` для пустого массива. Оба метода меняют массив. Операции с началом обычно требуют сдвигать остальные элементы, поэтому в больших очередях важен выбор структуры данных.

```js
const queue = ["B", "C"];
queue.unshift("A"); // 3
const next = queue.shift(); // "A"
// queue: ["B", "C"]
```

Для обычной очереди удобно добавлять через `push`, а забирать через `shift`: первым пришёл — первым обслужен.

**Короткая практика.** Добавьте `"a"` в начало `["b", "c"]`, затем удалите последний элемент. Верните массив. Ожидается `["a", "b"]`.

**Задача `serveNext(queue, newItem)`.** Сначала добавьте `newItem` в конец исходной очереди, затем извлеките первый элемент. Верните `{ served, queue }`.

Проверки: `(["A", "B"], "C") → { served: "A", queue: ["B", "C"] }`; `([], "C") → { served: "C", queue: [] }`.

**Контрольная 1.** Реализуйте историю из трёх действий: создать копию входных страниц, добавить новую страницу, удалить последнюю. Верните удалённую страницу и оставшуюся копию. Вход должен остаться неизменным. Объясните в комментарии, почему `const result = pages.push(page)` не сохраняет массив.

## 6. Диапазоны, объединение и распаковка

`slice(start, end)` возвращает новый массив от `start` до `end`, не включая `end`; исходный массив не меняется. Без `end` копирование идёт до конца. Отрицательные индексы отсчитываются с конца. `concat` и spread объединяют массивы в новую коллекцию. Деструктуризация извлекает значения, rest собирает остаток.

```js
const days = ["пн", "вт", "ср", "чт", "пт"];
const middle = days.slice(1, 4); // ["вт", "ср", "чт"]
const end = days.slice(-2);     // ["чт", "пт"]
const [first, ...rest] = days;
const all = ["вс", ...days];
const same = ["вс"].concat(days);
```

Разбор: `first` — строка, `rest` — новый массив из четырёх строк. `all` и `same` имеют одинаковое содержимое, но разные ссылки. Значение по умолчанию в `const [x = 0] = []` применяется к `undefined`, но не к `null`.

**Короткая практика.** Из `[10, 20, 30, 40]` деструктуризацией получите первый элемент и остаток. Верните `{ first, rest }`.

**Задача `pageItems(items, page, size)`.** Верните страницу элементов. `page` и `size` — положительные целые числа, нумерация страниц с `1`. Не менять вход.

Аналог: `letters.slice(2, 4)` возвращает элементы с индексами `2` и `3`. Начало страницы вычисляется как `(page - 1) * size`.

Проверки: `([1, 2, 3, 4, 5], 2, 2) → [3, 4]`; страница `3` → `[5]`; страница `4` → `[]`; пустой вход → `[]`.

## 7. Произвольное изменение: splice

`splice(start, deleteCount, ...newItems)` изменяет исходный массив и возвращает массив удалённых элементов. `deleteCount = 0` означает вставку без удаления. Если параметр `deleteCount` опущен, удаляются элементы от `start` до конца. Это отличается от явно переданного `0`.

```js
const letters = ["a", "b", "c", "d"];
const removed = letters.splice(1, 2, "x");
// letters: ["a", "x", "d"]
// removed: ["b", "c"]
letters.splice(1, 0, "y");
// letters: ["a", "y", "x", "d"]
```

Разбор: один вызов удалил два элемента начиная с индекса `1` и вставил один. Сохранённый результат содержит удалённое, а не итоговый массив. `slice` копирует диапазон, `splice` меняет коллекцию.

**Короткая практика.** Удалите `"b"` и `"c"` из `["a", "b", "c", "d"]`. Верните `{ removed, remaining }`.

**Задача `insertAt(items, index, value)`.** Создайте копию и вставьте `value` по индексу через `splice`, не удаляя элементы. Индекс гарантированно целый от `0` до длины включительно. Верните копию.

Проверки: `([1, 3], 1, 2) → [1, 2, 3]`; `([], 0, 5) → [5]`; вставка в конец; неизменность оригинала.

## 8. Циклы: сначала алгоритм, потом метод

`for` даёт индекс и управление шагом. `for...of` даёт значение; `items.entries()` позволяет получить пару `[index, value]`. `break` завершает цикл, `continue` пропускает текущую итерацию. Цикл сам по себе не возвращает готовую коллекцию — результат нужно накапливать.

```js
function positiveSum(numbers) {
  let sum = 0;
  for (const number of numbers) {
    if (number <= 0) continue;
    sum += number;
  }
  return sum;
}
positiveSum([-2, 4, 0, 3]); // 7
```

Разбор: накопитель создаётся один раз. Неподходящие числа пропускаются. На пустом массиве тело не выполнится, поэтому результат — `0`.

**Короткая практика.** Верните из `solution()` массив строк `["0: 10", "1: 20", "2: 30"]`, перебрав `[10, 20, 30]` обычным `for` и добавляя строки в новый массив.

**Задача `beforeZero(numbers)`.** Соберите новый массив элементов до первого нуля. Сам ноль и всё после него исключите. Используйте `for...of` и `break`.

Проверки: `[2, 3, 0, 4] → [2, 3]`; `[0, 1] → []`; `[2, 3] → [2, 3]`; `[] → []`. Вход не меняется.

## 9. Колбэк, forEach и map

Колбэк — функция, переданная другой функции для вызова. Методы перебора передают ей `(element, index, array)`. Имя параметра произвольно. `forEach` вызывает колбэк ради действия и возвращает `undefined`. `map` собирает возвращаемые колбэком значения в новый массив той же длины. В учебных задачах используем плотные массивы.

```js
const numbers = [2, 3];
const squares = numbers.map((number, index) => {
  return `${index}: ${number * number}`;
}); // ["0: 4", "1: 9"]

const messages = [];
const result = numbers.forEach(n => messages.push(n * 2));
// messages: [4, 6], result: undefined
```

Разбор: фигурные скобки у стрелочной функции требуют явного `return` для значения результата. `return` внутри `forEach` выходит только из текущего вызова колбэка. Он не останавливает весь перебор. Методы сами не требуют мутации входа, но ваш колбэк может его изменить.

**Короткая практика.** Через `forEach` соберите квадраты `[5, 10, 15]` в новый массив и верните его. Затем перепишите решение через `map`. Ожидается `[25, 100, 225]` в обеих версиях.

**Задача `priceLabels(prices)`.** Верните массив строк вида `"120 ₽"`, сохранив порядок. Вход — массив неотрицательных чисел. Используйте `map`.

Проверки: `[120, 0, 35] → ["120 ₽", "0 ₽", "35 ₽"]`; `[] → []`. Оригинал не меняется.

Дополнительно: `strings.map(parseInt)` опасно, потому что индекс станет аргументом системы счисления. Пишите `strings.map(value => parseInt(value, 10))`.

## 10. Отбор нескольких элементов: filter

`filter` вызывает предикат — функцию, отвечающую, подходит ли элемент. Элементы с истинным результатом остаются. Метод возвращает новый массив длиной от нуля до исходной, сохраняя порядок. Он не заменяет элементы на `true` и `false`.

```js
const prices = [50, 200, 0, 80];
const affordable = prices.filter(price => price <= 80);
// [50, 0, 80]
const flags = prices.map(price => price <= 80);
// [true, false, true, true]
```

Разбор: одинаковое условие внутри разных методов даёт разные формы результата. Выбирайте метод исходя из нужного выхода. При массиве объектов `filter` копирует внешний массив, но сохраняет ссылки на отобранные объекты.

**Короткая практика.** Верните из `[5, 12, 8, 130, 44]` числа больше `10`. Ожидается `[12, 130, 44]`.

**Задача `adults(users)`.** На входе объекты `{ name, age }`. Верните массив объектов с возрастом не менее `18`, сохранив порядок и исходный массив.

Проверки: возраст `17` исключается, `18` включается; пустой вход → `[]`; если никто не подходит → `[]`. Сначала сравните `age` в предикате, затем передайте предикат в `filter`.

**Контрольная 2.** `passingNames(students)` принимает `{ name, score }`, оставляет студентов с `score >= 60` и возвращает только их имена. Сначала решите циклом, затем `filter().map()`. Обе версии должны дать одинаковый результат на пустом массиве и граничных баллах.

## 11. Поиск значения и поиск объекта

`includes(value, fromIndex?)` возвращает boolean. `indexOf(value, fromIndex?)` возвращает первый индекс либо `-1`. `find(predicate)` возвращает первый подходящий элемент либо `undefined`. `findIndex(predicate)` возвращает его индекс либо `-1`.

```js
const tags = ["js", "vue", "js"];
tags.includes("js", 1); // true: найдётся элемент с индексом 2
tags.indexOf("js");    // 0
tags.indexOf("react"); // -1

const books = [{ id: 1, title: "А" }, { id: 2, title: "Б" }];
const book = books.find(item => item.id === 2);
const index = books.findIndex(item => item.id === 2);
// book: { id: 2, title: "Б" }, index: 1
```

Разбор: отдельный объект `{ id: 1 }` не равен другому объекту с теми же полями. Поэтому для поиска по полю нужен предикат. `includes` использует SameValueZero: в частности, `[NaN].includes(NaN)` даёт `true`; `indexOf(NaN)` не находит `NaN`. Не проверяйте индекс через `if (index)`: `0` — корректный индекс, а `-1` считается истинным.

**Короткая практика.** Верните `{ hasVue, reactIndex }` для `["js", "ts", "vue"]`. Ожидается `{ hasVue: true, reactIndex: -1 }`.

**Задача `nameById(users, id)`.** Верните имя первого пользователя с нужным `id`, иначе `null`. Входные объекты имеют `{ id, name }`. Используйте `find` и явно обработайте отсутствие результата.

Проверки: совпадение в начале; совпадение в конце; два одинаковых id — вернуть первое имя; отсутствующий id → `null`; `[] → null`.

## 12. Проверка условия: some и every

`some` отвечает, подходит ли хотя бы один элемент; останавливается после первого истинного результата. `every` отвечает, подходят ли все; останавливается после первого ложного. Оба возвращают boolean и сами не меняют массив.

```js
const ages = [19, 16, 22];
ages.some(age => age < 18);   // true
ages.every(age => age >= 18); // false
[].some(() => true);         // false
[].every(() => false);       // true
```

Разбор пустого массива: подходящий элемент не найден, поэтому `some` — `false`; нарушитель условия не найден, поэтому `every` — `true`. Если задача требует хотя бы один элемент, добавьте проверку длины.

**Короткая практика.** Для `[3, 7, 11]` верните `{ hasEven, allPositive }`. Ожидается `{ hasEven: false, allPositive: true }`.

**Задача `canSubmit(fields)`.** Объекты содержат boolean `isValid`. Верните `true`, только если массив не пуст и все поля валидны.

Проверки: `[] → false`; все валидны → `true`; один невалиден → `false`; единственное валидное поле → `true`.

## 13. Итог из коллекции: reduce

`reduce(callback, initialValue)` передаёт аккумулятор от одного элемента к следующему. Колбэк получает `(accumulator, element, index, array)` и должен вернуть аккумулятор следующего шага. Результат может быть числом, строкой, объектом или массивом. Для этих задач всегда задаём начальное значение явно.

```js
const prices = [10, 20, 30];
const sum = prices.reduce((acc, price) => acc + price, 0);
// шаги: 0 + 10 = 10; 10 + 20 = 30; 30 + 30 = 60
// sum: 60
```

Разбор: `0` задаёт тип и старт результата. На пустом массиве с начальным значением вернётся это значение. Без него пустой массив вызовет `TypeError`. Если вычисление проще выразить циклом, цикл также уместен.

**Короткая практика.** Найдите сумму `[1, 2, 3, 4]` через `reduce` с начальным значением `0`. Ожидается `10`.

**Задача `cartTotal(items)`.** Для массива `{ price, quantity }` верните общую стоимость. Оба поля — неотрицательные целые числа. Пример аналогичного накопления: `rows.reduce((sum, row) => sum + row.hours, 0)` суммирует часы; для корзины нужно вычислить вклад каждой строки.

Проверки: `[{ price: 10, quantity: 2 }, { price: 5, quantity: 3 }] → 35`; нулевое количество → вклад `0`; пустая корзина → `0`.

Дополнительная практика: посчитать число оценок `"good"` и `"bad"` в объект `{ good: 0, bad: 0 }`. Здесь аккумулятор — объект; возвращайте его после изменения счётчика. Универсальный словарь произвольных строк потребует учитывать специальные ключи объектов — это отдельная тема.

## 14. Сортировка и разворот

`sort(compareFn)` меняет исходный массив и возвращает его же. По умолчанию элементы сравниваются как строки по последовательностям кодовых единиц UTF-16. Для чисел нужна функция сравнения: отрицательный результат ставит `a` раньше `b`, положительный — позже, ноль сохраняет их относительный порядок в стабильной сортировке.

```js
const values = [10, 2, 100];
const sorted = [...values].sort((a, b) => a - b);
// sorted: [2, 10, 100], values: [10, 2, 100]
const descending = values.toSorted((a, b) => b - a);
// [100, 10, 2], исходник не изменён
const reversed = values.toReversed(); // [100, 2, 10]
```

Разбор: `reverse()` тоже меняет исходник; разворот не равен сортировке по убыванию. Для современных сред есть `toSorted` и `toReversed`, для других — копирование перед мутацией. Для текста можно использовать `a.localeCompare(b, 'ru')`; точный порядок зависит от выбранной локали и параметров.

**Короткая практика.** Верните две новые сортировки `[5, 1, 8, 3]`: по возрастанию и по убыванию. Исходный массив сохраните.

**Задача `cheapestFirst(products)`.** Верните новый массив объектов `{ name, price }` по возрастанию цены. При равной цене сохраните исходный порядок. Вложенные объекты менять не нужно.

Проверки: цены `[10, 2, 100] → [2, 10, 100]`; одинаковые цены; `[]`; неизменность входа и новая ссылка.

## 15. Строка из массива: join

`join(separator)` возвращает строку, не меняя массив. По умолчанию разделитель — запятая. `join('')` не добавляет разделители. Пустой массив даёт пустую строку. Элементы преобразуются в строки; `null` и `undefined` дают пустые части.

```js
const path = ["Главная", "Настройки", "Профиль"];
const label = path.join(" / ");
// "Главная / Настройки / Профиль"
```

Разбор: длина результата относится к строке, а не количеству элементов. Если перед объединением требуется отбор, выполните его отдельно. `filter(Boolean)` убирает не только `null`, но и `0`, `false`, пустую строку — используйте его только когда это действительно нужно.

**Короткая практика.** Соберите `["I", "love", "JS"]` в предложение. Верните `"I love JS"`.

**Задача `tagLine(tags)`.** На входе строки. Уберите пробелы с краёв каждой, исключите пустые и объедините через `", "`. Порядок и повторы сохраняйте.

Похожий подход: `parts.map(p => p.trim()).filter(p => p.length > 0).join(' / ')` собирает путь. Для задачи поменяется разделитель.

Проверки: `[" js ", "", " vue"] → "js, vue"`; `[" "] → ""`; `[] → ""`; `["js", "js"] → "js, js"`.

## 16. Вложенность и проверка входа

`flat(depth = 1)` возвращает новый массив, разворачивая вложенные массивы на заданную глубину. `flat(Infinity)` разворачивает все уровни обычного конечного вложенного массива. Объекты не превращаются в массивы автоматически. `Array.isArray` проверяет именно массив; `typeof []` возвращает `"object"`.

```js
const rows = [[1, 2], [3, [4]]];
rows.flat();  // [1, 2, 3, [4]]
rows.flat(2); // [1, 2, 3, 4]
Array.isArray(rows); // true
Array.isArray(null); // false
```

Разбор: глубина — число уровней раскрытия, а не желаемая длина. Копирование внешних массивов не означает глубокое копирование объектов.

**Короткая практика.** Полностью разверните `[1, [2, [3, [4]]]]`. Верните `[1, 2, 3, 4]`.

**Задача `collectPages(pages)`.** Вход неизвестного типа. Если это не массив, верните `[]`. Если это массив массивов чисел, объедините страницы на один уровень и верните результат. В корректном массиве каждый элемент гарантированно является страницей.

Проверки: `[[1, 2], [], [3]] → [1, 2, 3]`; `[] → []`; `null → []`; `{ a: 1 } → []`; строка → `[]`.

**Контрольная 3.** Для массива страниц товаров: объедините страницы, оставьте товары в наличии, верните их названия строкой через `", "`. Сначала назовите тип результата каждого шага. Исходные массивы и объекты должны остаться неизменными.

## 17. Изменение объектов без мутации

Копия массива не копирует его объекты. Чтобы изменить один объект без мутации, создайте новый массив через `map`, а для изменяемого объекта — новую копию через `{ ...object, field: value }`. Неизменённые объекты могут сохранить свои ссылки.

```js
function renameProduct(products, id, title) {
  return products.map(product =>
    product.id === id ? { ...product, title } : product
  );
}
```

Разбор: условие выбирает нужный объект. Spread объекта сохраняет остальные поля; `title` справа перезаписывает старое название. Объект со вложенными полями потребует копирования нужных уровней отдельно.

**Короткая практика.** Из массива `[{ id: 1, done: false }, { id: 2, done: false }]` получите новый массив, где только запись `id: 2` имеет `done: true`. Верните новый массив и проверьте, что исходный не изменился.

**Задача `toggleTodo(todos, id)`.** Верните новый массив, переключив `done` у записи с нужным уникальным id. Если id не найден, верните новый массив с прежним содержимым. Исходные объекты не менять.

Проверки: `false → true`; `true → false`; отсутствующий id; пустой массив. Изменённый объект должен иметь новую ссылку, неизменённые могут сохранять старую.

## 18. Цепочки и итоговый проект

Цепочка возможна, пока результат предыдущего шага поддерживает следующий метод. `filter → map → join` заканчивается строкой. После `some` будет boolean; вызвать на нём `map` нельзя. Сначала определите нужный выход, затем выбирайте операции.

```js
function availableLabels(products) {
  return products
    .filter(product => product.stock > 0)
    .sort((a, b) => a.price - b.price)
    .map(product => `${product.title}: ${product.price} ₽`);
}
```

Разбор: `filter` создал новый внешний массив, поэтому последующий `sort` меняет именно его. Исходный порядок `products` сохранён; объекты не изменяются. Если убрать `filter`, перед `sort` понадобится копия.

**Короткая практика.** Из `[1, 2, 3, 4, 5, 6]` одной цепочкой оставьте чётные числа, умножьте каждое на `10`, отсортируйте по убыванию. Ожидается `[60, 40, 20]`.

**Итоговая задача `buildCatalog(products, maxPrice)`.**

Вход: массив `{ id, title, price, inStock }`. `price` и `maxPrice` — неотрицательные целые числа; `inStock` — boolean; `id` уникальны. Требуется:

1. Оставить товары в наличии с `price <= maxPrice`.
2. Отсортировать по возрастанию цены, сохраняя порядок при равенстве.
3. Вернуть объект `{ ids, labels, total, hasItems }`.
4. `ids` — массив id отобранных товаров; `labels` — строка `"Название: цена ₽"` через `"; "`.
5. `total` — сумма цен отобранных товаров, `hasItems` — наличие хотя бы одного результата.
6. Не изменять исходный массив и его объекты.

Пример входа:

```js
const products = [
  { id: 1, title: "Книга", price: 300, inStock: true },
  { id: 2, title: "Ручка", price: 50, inStock: false },
  { id: 3, title: "Тетрадь", price: 100, inStock: true }
];
// buildCatalog(products, 300) должен вернуть:
({
  ids: [3, 1],
  labels: "Тетрадь: 100 ₽; Книга: 300 ₽",
  total: 400,
  hasItems: true
});
```

Проверки: цена на границе включается; отсутствие товаров в наличии; все цены выше лимита; одинаковые цены; пустой вход; товар с нулевой ценой. Для отсутствия результатов ожидается `{ ids: [], labels: "", total: 0, hasItems: false }`. Проверяется неизменность исходных объектов и порядка входа.

Разбейте решение на переменную с отобранными и отсортированными товарами и отдельную сборку четырёх полей результата. Не повторяйте всю цепочку для каждого поля.

## Дополнение: применение в Vue и React

Этот раздел изучается после основ конкретного фреймворка.

Во Vue 3 реактивные массивы отслеживают `push`, `splice`, сортировку и запись по индексу. Мутация сама по себе не ломает реактивность. Но производные списки лучше вычислять без изменения исходных данных:

```js
const sortedUsers = computed(() =>
  [...users.value].sort((a, b) => a.name.localeCompare(b.name, 'ru'))
);
```

В React состояние обновляют новой ссылкой. Если следующее состояние зависит от предыдущего, используйте функциональную форму сеттера:

```js
setUsers(previous => [...previous, newUser]);
setUsers(previous => previous.filter(user => user.id !== removedId));
setUsers(previous => previous.map(user =>
  user.id === changedId ? { ...user, name: newName } : user
));
```

Практика для Vue: отобразить список с устойчивым `:key="user.id"`, добавить поиск через `computed` и сортировку копии. Практика для React: отобразить список с `key={user.id}`, добавить пользователя, удалить по id и изменить имя без мутации состояния. Проверить сохранение остальных свойств и поведение при пустом списке.

## Дополнение: асинхронность и разреженные массивы

`forEach` не ожидает промисы, возвращённые асинхронными колбэками. `await` внутри `async`-колбэка работает, но сам `forEach` не ждёт завершения этих операций. Для последовательной работы используйте `for...of` с `await`; для совместного ожидания нескольких операций — `await Promise.all(items.map(async item => ...))`. Перед этим нужны отдельные уроки про Promise и обработку ошибок.

Пропуск в массиве отличается от элемента со значением `undefined`: `0 in [,]` — `false`, `0 in [undefined]` — `true`. Методы `map`, `filter`, `forEach` пропускают отсутствующие элементы; `map` сохраняет пропуски в результате. В основном модуле такие массивы исключены из входных данных.

`fill(value)` меняет массив и возвращает тот же массив. При `Array(3).fill({ done: false })` все три элемента ссылаются на один объект. Для трёх независимых объектов: `Array.from({ length: 3 }, () => ({ done: false }))`. Этот материал изучается после ссылок и колбэков.

## Правила проверки на платформе

- Для каждого урока: короткая практика в редакторе, самостоятельная функция и разобранный аналог перед редактором.
- Проверять строго тип, содержимое, порядок и структуру результата. `undefined` должен отличаться от отсутствующего ключа объекта и от `null`; `NaN` — от `null`.
- Для требований «не менять вход» сравнивать аргументы до и после выполнения, включая поля объектов. Для требований о ссылках проверять их внутри того же worker до передачи результата в UI.
- Там, где требуется конкретный метод или цикл, проверка результата сама по себе не доказывает его использование. Обозначать это как учебное требование для разбора либо добавлять отдельную проверку синтаксического дерева. Не выдавать прохождение тестов за доказательство применения метода.
- Тестировать обычный случай, пустой вход, один элемент, отсутствие совпадений, дубликаты и границы условия — только в рамках описанного контракта.
- Каждый тест должен сообщать вход, ожидаемый результат и фактический результат. Отдельно сообщать о мутации входа и неправильной ссылке.
- Поддерживать черновики отдельно от принятого результата. Изменение кода сбрасывает статус проверки; тайм-аут защищает интерфейс от бесконечного цикла.
- Список методов и результаты на клиенте доступны пользователю. Такая проверка предназначена для обучения.
